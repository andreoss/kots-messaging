# kots-mq

Provider-agnostic message-queue library on Cats and Cats Effect, cross-built
for Scala 2.13 and 3. One algebra in `core`; every broker is an adapter over
it. The core depends on Cats and Cats Effect only.

## Algebra

`Producer[F, A]` publishes; `Consumer[F, A]` hands out `Delivery[F, A]`
values carrying `ack`, `reject` and `extend`. Settling is the caller's:
nothing is acknowledged because an effect happened to complete.

```scala
import cats.effect.IO
import cats.syntax.all._
import kots.mq._
import kots.mq.mem.MemBroker

val destination = Destination("orders")

for {
  broker <- MemBroker.create[IO, String](Entropy.system[IO])
  _ <- (broker.producer(destination), broker.consumer(destination, ConsumerSettings.default))
         .tupled
         .use { case (producer, consumer) =>
           producer.send(Message.of("one")) *>
             consumer.receive.flatMap(_.traverse_(_.ack))
         }
} yield ()
```

`ConsumerSettings` carries the lease, the attempt budget, the prefetch bound,
the `Backoff` policy and an optional dead-letter destination.

A handler says what should happen to its message — `Settlement.Done`,
`Retry`, `Release`, `Drop` or `DeadLetter` — and `Semantics.process` settles
it, renewing the lease while the handler runs and bounding how long it may
take. `Semantics.atMostOnce` and `atLeastOnce` remain for the two plain
modes. `BatchingProducer` gathers what callers publish one at a time into
batches; `RateLimit.tokenBucket` paces a consumer; `Metered` binds the
metrics port; `Transcode` carries the algebra from wire bytes to a typed
payload; `Broker.admin` states a destination's depth and topology, and
`Broker.events` reports what the broker says about itself.

## Brokers

| Broker | Module | Acknowledgement | Capabilities | Tier |
| --- | --- | --- | --- | --- |
| In-memory | `mem` | in-process lease | batch, delay, dead-letter, lease extension, topology, expiry | unit |
| Apache Kafka | `kafka` | offset commit | batch, dead-letter, ordering group, topology | e2e |
| RabbitMQ | `amqp` | channel ack | batch, delay, dead-letter, topology, expiry | e2e |
| Amazon SQS | `sqs` | delete message | batch, delay, dead-letter, lease extension, topology | e2e |
| ActiveMQ, Artemis | `jms` | per-message ack | batch, dead-letter, expiry, and delay and priority where the provider has them | e2e |

`stream` adds an fs2 layer, `interop` carries the algebra into the other
effect system, `prometheus` binds the metrics and depth ports, `bench` times
the in-memory adapter against a bare queue. Every adapter passes the same
contract suite, and an optional feature is tested only where the adapter
declares it.

## Build and test

    sbt -batch +test

The unit tier needs no services.

## E2e tier

The adapters over live brokers run against the compose stack:

    docker compose up -d --wait
    ./scripts/artemis-init.sh
    sbt -batch kafka/test amqp/test sqs/test jms/test prometheus/test
    docker compose down

The metrics suite serves a live workload on `127.0.0.1:19096` and asserts the
composed Prometheus scrapes its series back.
